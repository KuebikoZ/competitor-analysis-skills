# 完善竞品分析报告

## 角色与目标

你在帮**氢离子（Ali-Doctor）产品经理**完善一份竞品调研报告。报告作者已经完成了第 2 部分——竞品的**功能盘点**（逐模块罗列竞品功能、截图等）。你的任务是基于这份盘点，补齐前后两块内容并统一排版：

1. **第 1 部分「总结」**：竞品的优点、缺点、对氢离子的启示。
2. **第 3 部分「功能对比清单」**：竞品 vs 氢离子的功能对比表格。
3. **格式**：设置规范的标题层级、在文首插入纯文本目录。

**成功标准**：产出的 markdown 是一份**完整的、可直接使用的独立文档**——包含总结、作者原有功能盘点全文、功能对比表格，三部分都完整呈现，不使用占位符或省略号。

## 三个输入

调用时用户会提供（若缺失，主动向用户索要）：

| 输入 | 用途 |
| --- | --- |
| **当前竞品分析文档** | 已完成的第 2 部分功能盘点，是你所有分析的事实来源。 |
| **参考示例『调研：医渡智循』** | 目标产出的风格与结构范本，已随 Skill 附带，见 `references/示例-调研医渡智循.md`。 |
| **氢离子功能清单** | 判断"氢离子是否具备"某功能的**首要依据**，已随 Skill 附带，见 `references/氢离子功能清单.md`。 |
| **氢离子使用手册 PDF**（补充） | 作为功能清单的补充参考，已随 Skill 附带，见 `references/氢离子使用手册.pdf`。手册以图片页面形式展示氢离子各功能的实际界面截图，可辅助确认功能细节。 |

### 氢离子能力判断的优先级链

判断"氢离子是否具备"某功能时，按以下优先级依次查找：

1. **氢离子功能清单**（最优先）：读取 `references/氢离子功能清单.md`，该文件结构化列出了氢离子的全部功能模块和核心能力。
2. **氢离子使用手册 PDF**（补充）：如需确认功能清单中未明确覆盖的细节，读取 `references/氢离子使用手册.pdf`（图片形式，含实际界面截图），以验证具体交互和功能边界。

若以上来源均未覆盖，如实标注"待确认"并提示用户补充，不要臆造。

### 参考示例的使用方式

参考示例较长，无需整篇照抄。**首次执行时快速浏览 `references/示例-调研医渡智循.md`**，重点看它的总结分层方式和表格结构，模仿其**结构和颗粒度**，而非照搬医渡智循的具体功能内容。

## 工作流

严格按顺序执行，先完成前置判断，再执行三步。

### 前置步骤：判断端类型（移动端 / PC端）

在开始正式产出前，**必须先确定竞品文档描述的是移动端还是 PC 端产品**。判断方法：

1. **从文档内容推断**：查看功能盘点中是否有明确线索——如提到"APP""移动端""手机""iOS/Android"则为移动端；如提到"Web 端""PC 端""网页版""浏览器"则为 PC 端。
2. **无法判断时主动提问**：如果文档中未明确标注端类型，**必须先向用户提问确认**，不得自行假设。提问示例："您提供的竞品功能盘点是基于移动端（APP）还是 PC 端（Web）的体验？这会影响功能对比的范围。"

确定端类型后，后续所有对比（总结 + 功能对比清单）都**只在同一端类型下进行**：

- **移动端文档** → 氢离子侧只取移动端（APP）功能进行对比。
- **PC 端文档** → 氢离子侧只取 PC 端功能进行对比。
- **严禁跨端对比**：不得将竞品的移动端功能与氢离子的 PC 端功能混合比较，反之亦然。

### 第一步：生成「总结」

总结分三小节，**篇幅精简**——这是给决策者快速扫读的，不要长篇大论。

- **1.1 竞品优势**：从功能盘点中提炼竞品做得好的地方。**按体验维度分组**（如"问答体验""知识库生态""文献检索"等），每组用一两句点出关键能力，而非平铺流水账。
- **1.2 劣势**：竞品体验上的短板、未跑通的能力、交互瑕疵、质量不稳定之处。分点、简洁。
- **1.3 启示**：落到**氢离子该怎么做**——哪些值得借鉴补齐、哪些是氢离子已有的优势要继续强化。务必指向氢离子的具体动作。

写作要点：结论必须能从功能盘点中找到支撑，不要引入盘点里没有的事实；语言凝练，一个点一句话讲清。

### 第二步：生成「功能对比清单」

功能对比分为**两个区域**呈现。

**同端对比原则**：根据前置步骤确定的端类型，竞品和氢离子都只取**同一端**的功能进行对比。严禁跨端对比（例如不得将竞品 Web 端的功能与氢离子 APP 端的功能放在同一行比较）。

#### A. 功能对比表（双方都涉及的功能）

只有**两边都涉及**（都有、或一方有一方无但属同类功能）的功能才逐条对比。按功能模块分表，用 ✅/❌ 标注：

| 功能 | [竞品名] | 氢离子 | 标注 |
| --- | --- | --- | --- |
| 文件上传提问（PDF/Word） | ✅ | ❌ | 🔴 |
| 生成分享图片 | ❌ | ✅ | 🟢 |
| AI 原文总结 | ✅ | ✅ | |

**标注规则**（简洁互斥、三选一）：
- **🔴**：竞品有、氢离子没有——氢离子的缺口，需关注是否补齐。
- **🟢**：氢离子有、竞品没有——氢离子的优势项。
- **留空**：双方都有，属对齐项。

在表格前用一句话说明标注含义。

#### B. 竞品独有功能（合并列出）

如果竞品有整块能力是氢离子完全不涉及的（如"写综述""森林图 Meta 分析""用药核查"等全新能力领域），无需逐条展开 ✅/❌ 对比——合并为**「竞品独有功能」**一组，用列表简要列出功能名称和一句话描述即可。这些已在总结 1.3 启示里以"值得借鉴补齐"的形式强调过，对比表里不再重复展开。

示例写法：

```markdown
#### 竞品独有功能（氢离子暂无对标能力）

- **写综述**：输入主题 → 生成提纲 → 逐章检索证据撰写 → 导出 Word
- **森林图**：随机效应模型合并同源研究，输出 NNT、纳入排除表
- **用药核查**：907 条规则引擎核对配伍/肾功能/基因型风险
```

### 第三步：设置标题格式并加目录

- 统一标题层级：`#` 报告标题 → `##` 一级章节（1 总结 / 2 [竞品名]功能盘点 / 3 功能对比清单）→ `###` 小节。保持编号连续、层级一致。
- 在文首（报告标题之后）插入**纯文本目录**——只用缩进列表列出章节结构，**不使用 `[text](#anchor)` 超链接格式**（因为不同文档平台对中文标题锚点解析规则不同，链接跳转经常失效）。
- **将作者的第 2 部分功能盘点原文完整嵌入**产出文档中，只做必要的标题层级归一，不改动其事实内容、不省略、不用占位符代替。特别注意：**所有图片 Markdown 链接必须逐字符原样复制**，不得编造任何 URL（详见下方「图片链接处理规则」）。

## 交付格式

输出一份**完整的** markdown 文档，整体骨架：

```markdown
# [竞品名]竞品调研报告

## 目录

1 总结
  1.1 竞品优势
  1.2 劣势
  1.3 启示
2 [竞品名]功能盘点
3 功能对比清单
  3.1 功能对比表
  3.2 竞品独有功能

## 1 总结
### 1.1 竞品优势
### 1.2 劣势
### 1.3 启示

## 2 [竞品名]功能盘点
（此处完整嵌入作者上传的功能盘点原文，包含所有表格、截图链接等，不省略）

## 3 功能对比清单
### 3.1 功能对比表
（分模块的 ✅/❌ 对比表，仅包含双方都涉及的功能）
### 3.2 竞品独有功能
（合并列出氢离子暂无对标能力的整块功能）
```

## 图片链接处理规则（关键约束）

功能盘点原文中包含大量 Markdown 图片链接（`![alt](url)`），在嵌入第 2 部分时**必须逐字符原样保留**，具体要求：

1. **严禁伪造 URL**：不得生成任何不存在于原始文档中的图片 URL。每一个 `![...](https://...)` 都必须能在用户提供的原始功能盘点中找到完全一致的对应。
2. **严禁简化或归纳图片**：即使某行有十几张图片，也必须全部保留，不得用"详见原调研文档"、"（共 N 张截图）"等文字描述替代。
3. **严禁修改 URL 中的任何字符**：包括资源路径（`res/` 后的 ID）、图片文件名（`img/` 后的 UUID）都不能改动。
4. **alt 文本原样保留**：如果原文是 `![{5DE4A92E-75DD-4036-AF1A-7ABEFC6663E5}.png](url)` 则保持该 alt 文本不变，不要简化为 `![image](url)`。
5. **图片间的描述文字也需保留**：如 `侧边栏<br>![img](url1)<br>专业版<br>![img](url2)` 中的"侧边栏""专业版"等标注文字必须保留。

**自检方法**：输出完成后，对第 2 部分中所有图片 URL 做逆向检查——如果一个 URL 在原始输入文档中搜索不到完全匹配，说明是幻觉生成的，必须修正为原文中的正确链接。

## 边界与注意事项

- **不跨端对比**：功能对比必须在同一端类型下进行（移动端对移动端、PC 端对 PC 端），不得混合。
- **不臆造功能**：竞品能力只来自作者的功能盘点；氢离子能力按优先级链判断。无法确认的标"待确认"。
- **不臆造链接**：第 2 部分中的所有图片链接必须与用户原始输入完全一致，逐字符不差。
- **篇幅克制**：总结部分尤其要短，优点/缺点/启示各自分点即可，避免注水。
- **完整交付**：产出必须是完整独立的文档。第 2 部分功能盘点原文全文嵌入，不得省略或用占位符替代。
- **占位符替换**：把模板中的 `[竞品名]` 全部替换为实际竞品名称。
- **风格对齐但不照抄**：模仿参考示例的结构与颗粒度，内容必须来自当前竞品文档，不要混入医渡智循的具体信息。
- **目录不做跳转**：目录为纯文本缩进列表，不使用超链接锚点。
